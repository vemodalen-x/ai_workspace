## 评分方法

11 个维度等权，每项 10 分。0 表示缺少实现，4 表示局部功能可运行，6 表示已有可用路径但关键环境或失败处理仍有缺口，8 表示核心路径及主要异常有执行证据，10 要求在目标设备、操作系统、真实 Provider 和长期工作负载上通过对应验收。半分表示两个锚点之间的工程判断。视觉得分只能依据组件、交互路径和已执行验证，尚需桌面与移动端实测。总分按未舍入分项求平均，再保留一位小数。

## 合并恢复

用户批准后，SQLite 先持久化 `applying`，Git 再执行原有的源提交、目标提交、分支与干净工作区检查。服务正常启动时，或用户在 inspector 选择 **Check target branch** 时，系统读取原目标分支。

| 目标分支的 Git 证据                    | 处理结果                                                      |
| -------------------------------------- | ------------------------------------------------------------- |
| 指向预览提交，或该提交是当前目标的祖先 | 在同一个 SQLite 事务中记录 approved 与唯一的 GitMerged 事件。 |
| 仍指向原目标 SHA                       | 恢复 pending，用户可重新审查并批准。                          |
| 分支已转到其他历史                     | 标记 superseded，检查历史后可创建新预览。                     |
| 仓库或 ref 无法读取                    | 保留 applying，恢复访问后可再次对账。                         |

对账仅查询 Git。硬崩溃留下的 server.lock 仍需按 README 排查旧进程后处理。外部重写历史可能抹去曾发生过的合并证据。

## 接入本地实验指标

任务中启用 **Track as an AI experiment**，填写组名、数据集版本和 seed，把验证命令配置成实际评估程序的 JSON argv，例如 `["python", "evaluate.py"]`。在现有 Python 评估代码计算出数值后调用下列函数。示例中的参数应来自该次评估。

```python
import json

def report_metric(name, value, unit, step):
    point = dict(name=name, value=float(value), unit=unit, step=int(step))
    print("WORKSPACE_METRIC " + json.dumps(point, allow_nan=False), flush=True)

# 在评估代码中调用，如 report_metric("val_mIoU", computed_miou, "ratio", epoch)
```

在 **Compute nodes → Compare experiment runs** 对照同组 Run。每个 name/unit 组合展示最大 step 的最新一次值，最多 32 组，每行最多 2048 字节。只采集显式批准的本地验证命令 stdout。无效标记行计入报告的 ignoredMetricLines。通过的验证报告会保留在 command-validation.json，比较表检查报告 commit 与 Run.resultCommit。界面依据脚本自报值展示，数据集、样本量、评估方法和 seed 的正确性仍须由实验者保证。

同组对比时应检查数据版本、单位及 step。例如 ratio 量纲的 0.75 和百分制的 75 需要统一口径。实验结束时保留当前留存窗口内的共享设备样本统计；采样间隔、窗口过期及同卡其他进程仍会影响读数解释。

## 验证和下一次验收

- `npm run check` 执行类型、lint、核心测试和构建；`npm run test:production` 启动编译产物并检查 API、静态页面和关闭。
- 新回归覆盖提交偏移、合并意图写入后中断、Git 成功后数据库事件写入失败、目标分支继续推进、无关分支历史、指标跨 chunk/异常行、验证脚本实际 stdout、硬件历史轮替后的查询。
- `npm run test:e2e` 默认使用独立测试端口和临时数据库。本次尝试运行 Chromium 用例时缺少对应 headless shell，官方安装下载所得 ZIP 无效，浏览器交互验收仍待执行。在可用开发机安装匹配的浏览器后运行 `npx playwright install chromium` 和 `npm run test:e2e`。
- 下一轮优先用一台实际 Linux GPU 服务器和 Windows 控制端执行 `npm run check:fleet -- fleet.local.json`，再跑一个有明确输入摘要、吞吐率和质量指标的小实验。对原始训练日志、设备 UUID、代码 SHA 和 UI 数值逐项核验。详细操作见 [多机部署指南](experiment-fleet.md)。
