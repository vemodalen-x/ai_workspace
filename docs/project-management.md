# 加载已有项目与本机工具历史

项目区的 `+` 或项目页的添加按钮可加载已有文件夹。支持输入绝对路径，也可在应用内浏览**服务所在电脑**的本地文件夹并选择；远程浏览器不能用本地上传控件代替服务器目录选择。目录无需重新创建，加载不会执行 `git init`、安装依赖或复制原工具数据。

路径经 `realpath` 规范化并检查目录类型与读取/遍历权限。重复加载同一规范路径返回已有项目；曾移除的项目恢复原 ID 和工作区历史，不产生重复登记。名称和并发设置保留原值。符号链接别名指向同一目录时同样去重。文件、相对路径、不存在和权限不足的目录会给出错误，表单输入保持不变。

没有初始提交、非仓库根目录或未通过 Git 校验的文件夹可加载并查看历史，但不能建立执行任务。工作区任务和命令试验仍使用既有 Git/worktree 隔离机制；不会为加载文件夹而修改它。

## 数据位置及关联依据

本次检查了本机 Codex CLI 0.169.0 与 Claude Code 2.1.177 的实际文件结构。工具存储格式可能随版本变化，无法识别时会显示部分可读或无法读取。

| 数据             | 查找位置                                                                                                                                               | 关联方式                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Codex 会话       | `$CODEX_HOME/sessions`、`archived_sessions`，默认 `~/.codex`                                                                                           | JSONL 的 `session_meta.payload.cwd`，会话 ID 来自 `payload.id`                |
| Codex 索引       | 最新的 `state_N.sqlite`，只读打开                                                                                                                      | `threads.cwd` 精确匹配；用 `id` 补充可读会话标题，缺失 rollout 计入不完整状态 |
| Claude Code 会话 | `$CLAUDE_CONFIG_DIR/projects/*/*.jsonl`，默认 `~/.claude`                                                                                              | JSONL 内的 `cwd` 和 `sessionId`；目录编码只用于定位，不能作为归属证据         |
| 项目配置与指令   | 项目 `AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md`、`.claude/CLAUDE.md`、`.codex/config.toml`、`.claude/settings.json`、`.claude/settings.local.json` | 所选项目目录                                                                  |
| 全局配置与指令   | Codex home 的 `config.toml`、`AGENTS.md`、`AGENTS.override.md`；Claude home 的 `settings.json`、`CLAUDE.md`                                            | 标注全局作用域，不误当作项目专属文件                                          |
| 上级指令         | 父目录中的 `AGENTS.md`、`CLAUDE.md`、`.claude/CLAUDE.md`                                                                                               | 标注上级目录；最多 30 层                                                      |

工作目录双方使用规范化后的绝对路径**精确匹配**。父目录、子目录和不同 worktree 不自动归为同一个项目；不存在的源工作目录不猜测归属。全局 `history.jsonl` 中的交互输入不等同于完整会话，认证、凭据、插件缓存与日志数据库不会当作项目历史导入。会话标题从可读取的 Codex SQLite 索引补充，其他会话展示原始工具会话 ID。

这是只读文件清单，不是对工具最终配置优先级、信任策略或动态插件的完整模拟。设置文件展示键名，避免展示凭据值；指令文件显示有界文本。缺失、权限问题、无效 JSON、符号链接与不兼容结构不会默默当作空数据。

自动发现的历史与已有手动挂载 Claude 会话入口并存。自动发现只展示与当前目录匹配的本机会话；手动挂载仍可显式查看来自其他目录的 Claude 会话。二者都不会创建受管 Run，也不会启动或接管原终端进程。会话内容中的用户输入、代码、命令保持原文，沿用现有密钥脱敏规则，不展示 thinking 与工具结果负载。

扫描有界：每次最多检查 10,000 个路径，最多读取 64 MiB 会话前缀；只显示最近 300 个匹配会话。目录层级范围为 Codex sessions 下 4 层和 Claude projects 下 1 层，跳过子代理嵌套历史。会话初始元数据最多读取 1 MiB；输出只读取最近 1 MiB、200 条消息、每条最多 32,000 字符。损坏记录跳过，未完整写入的最后一行留待下次读取。达到限制显示部分结果或截断。列表可手动刷新，选中会话每 5 秒更新；服务端扫描缓存 15 秒，路径归属和安全检查在读取时重验。

## 移除项目

列表行右侧移除按钮或项目页“移除项目”打开简短确认。`DELETE /api/projects/:id` 只将登记标记为移除，并隐藏其工作区历史。**不会删除项目文件夹、worktree、原工具会话或工具配置**，不调用 Git 清理，不删除数据库历史。再次加载同一目录可恢复。

存在 queued / starting / running / orphaned 执行或命令试验时拒绝移除，先停止或核对执行。归档项目原有恢复入口继续保留；移除与归档的区别是被移除项目不显示在登记和归档列表中。

## API 与验证

新增认证 API：`GET /api/local-folders?path=...`、`GET /api/projects/:id/local-history?refresh=true`、`GET /api/projects/:id/local-history/:session`。历史 ID 为服务生成的路径哈希；客户端不能传入任意 transcript 路径。读取时拒绝记录符号链接、越界与被替换文件；SQLite 用只读模式打开，不依赖其 rollout 路径访问任意文件。

验证命令：`npm run check`、`npm run test:e2e`、`npm run test:production`。测试覆盖目录浏览、重复登记、移除与恢复、权限与路径失败、双工具归属、原文保留、配置键名、损坏/缺失/变更/符号链接记录，以及中英文流程。
